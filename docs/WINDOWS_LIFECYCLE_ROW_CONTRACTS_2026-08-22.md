## Window registration、runtime HWND、DPI後supported predicate（正本）

`exactly six`は登録top-level surface inventoryの件数であり、runtime cardinalityを6へ固定しない。
登録surfaceはMain、Setup、Settings、Graph、Threads、Legalの6個、HelpはMain内surfaceで追加HWND=0。
runtimeのopen HWNDはMain=1に対しchild subset=Setup/Settings/Graph/Threads/Legalの各0..1、合計1..6
である。各childはsingletonで、5 childを全て開いた時だけruntime HWND=6となる。childを閉じた後は
そのHWNDを0へ戻し、registered inventoryを減らさない。

各surface・monitor・DPI・logical client sizeのsupported predicateは次のANDで固定する。

```text
client_threshold(surface) AND frame_fit(surface, monitor)
client_threshold(fixed) = logical_client_width >= 900 AND logical_client_height >= 480
client_threshold(Graph) = logical_client_width >= 700 AND logical_client_height >= 480
frame_fit = DWM.visible_frame が対象 MONITORINFO.rcWork に完全包含
```

`frame_fit`はDPI変換後に取得したvisible frameのphysical origin/width/heightで判定し、
`left >= rcWork.left`、`top >= rcWork.top`、`right <= rcWork.right`、`bottom <= rcWork.bottom`を
全て満たす。logical clientの900×480/700×480は必要条件であり、client thresholdだけではsupported
としない。client thresholdとframe-fitのANDがsupportedの十分条件である。

reopenではlast stable OS rectを、現在存在するいずれかのmonitorの`MONITORINFO.rcWork`へvisible
frame全体が包含される時だけ復元する。monitor除去または解像度縮小で無効なら、Mainはforeground
monitor→primary、childは有効owner monitor→primaryの順で、`topology_recovery center`を一度だけ
実行し、選択理由をrawへ記録する。通常のtimer/poll/drag後のrecenterは0件で、無効reopen時の
一度だけの`topology_recovery center`だけを例外とする。どのmonitorもsupported
predicateを満たさない場合は`unsupported_scope`として記録し、PASS値を捏造しない。

この追加の目的は、登録上の6 surfaceとruntimeの1..6 HWNDを分離し、DPI変換後のframe-fitを含む
supported判定と、display topology変化時の安全なreopenを行固有契約へ固定することである。理由は、
runtime cardinalityの固定、client thresholdだけのsupported判定、無効rectの復元、timer補正を許すと、singleton、
focus、frame、viewportの受入結果が誤るためである。X版の値、期間、状態、順序、データ所有権、
失敗時保持は不変であり、追加するのはWindows OS frame/topology/lifecycle表現だけである。
証拠計画は、同一artifact SHAで登録inventory、runtime HWND集合、child singleton、logical→physical
round、DWM/rcWork包含、reopen fallback/reason、timer/poll/drag recenter=0をraw manifestへ保存し、
実装担当とは別の評価者が独立再計算する。証拠未取得のため全行は`INCONCLUSIVE`のままとする。
