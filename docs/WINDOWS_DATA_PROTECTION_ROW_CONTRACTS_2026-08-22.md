### REST拒否応答・header・DB副作用の共通matrix

`GET /v1/health`、`GET /v1/status`、`GET /v1/details`だけが200を返す。既知pathの
`HEAD/POST/PUT/PATCH/DELETE/OPTIONS`等の全non-GETはJSON 405、unknown、case-altered、末尾slash、
query付きpathはmethodを問わずJSON 404である。404/405を含む全responseは
`Content-Type: application/json; charset=utf-8`、`Cache-Control: no-store`、header aggregate 8KiB以下で、
response header allowlistはこの2つと固定body時の`Content-Length`だけとし、固定bodyの`Content-Length`はUTF-8 body bytesと一致し、
`Set-Cookie`/`Location`/`Content-Encoding`/`WWW-Authenticate`/proxy/authentication headerなど追加headerを返さず、
SQLite transaction、WAL/SHM、migration、prune、backup、row/hash、PublishedPairを変更しない。

`connectionSelector`）とする。profileは`none|wsl|sshConfigAlias`、selectorはWSL exact distribution tokenまたは

## 必須保持値と数値境界

- 現行正本の数値をfixtureへ固定する: status transfer body `64 KiB`、details transfer body `32 MiB`、response header aggregate `8 KiB`、history periods `128`、history samples `100000`、threads `256`、models `3`、HTTP timeout `3 s`、UsageStore busy timeout `2 s`、daemon interval `5..3600 s`（default `60 s`）、reset hint/lease `4 KiB`、stale lock `24 h`（diagnostic only）、internal snapshot `1 MiB`、JSONL line `4 MiB`、session file `256 MiB`、session total `2 GiB`。hint pathは`history/usage_reset_hint.json`で、internal snapshotとREST transfer bodyは別resourceである。
- reset hintは`now >= reset_at`で`expired`へ進み、旧期間の新規source変更をscan/DB rowへ帰属させない。source logは保持し、current AuthEpoch/opaque nonceを持つfresh authenticated hint（`reset_at > now`）受領後だけbackfill latchを1回消費する。logout/account切替では旧hintを`tombstoned`にし、hint/DBへ個人識別値を保存しない。
- transaction batchは最大1024 rowsかつ1MiB、backfill latchはoutage epochにつき1回、scan/restart retryは1回、same-callback retryはbusyの1回以外0回とする。既存正本値を推測で上書きせず、各上限とbyte counting pointをmanifestへ固定する。
- 追加負荷の境界は、daemon idle（入力fingerprint不変）を60秒観測してCPU平均を1% of one core以下、RSS増加を16 MiB以下、同一周期のJSONL全走査/DB書込み/retryを0回とする。入力変化時は1周期につき最大1走査・1 transaction、失敗時retryは次周期まで1回に限定する。実測未取得は`INCONCLUSIVE`とする。
- backup保持上限は3、`.bak.1`を最新verified、`.bak.3`を最古verifiedとし、各世代のquick_check、row count、deterministic fingerprint、reset-period境界、file SHA、mode（DB dir 0700、backup 0600）を同一manifestへ入れる。一activationで作成できる新generationは最大1件で、成功した別activationにより0→1→2→3と蓄積する。同一snapshotの複製で不足世代を埋めない。各初回生成とrotation failure retentionを記録する。
- migration candidateは別名DB、全row/schema/一意key/period validate、旧DB/旧backup/old memory保持、atomic switchの順序を固定し、old-schema reject、success、failureの3経路を行ID別にする。restoreは明示operationだけで、通常起動の自動復元を許可しない。
- 実装後の製品証拠は同一artifact SHAでraw request/response、DB trace、daemon PID/lock、backup inventory、failure log、独立再計算を揃える。
