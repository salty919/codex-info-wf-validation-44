# 導入と起動ガイド

## 目的

Codex Infoを自分のWSL環境で起動し、認証状態・レートリミット・利用履歴をX Windowで確認できる状態にします。

## 全体の流れ

1. 事前準備を確認する  
2. リポジトリを取得して起動する  
3. Codex認証を完了する  
4. 起動後の画面が期待どおり表示されるか確認する  
5. 必要なら環境変数で表示状態や保存先を調整する

この順で進めると、失敗が起きた場合の原因を切り分けしやすくなります。

## 事前準備

### 1) RustとCargo

初回はRustが未導入でも、`run.sh`が標準のCargoパスとRustupのパスを探します。未導入の場合は次で導入してください。

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
```

### 2) X Windowの起動確認

WSLg/ X サーバーが利用可能であることを確認します。

```bash
echo "$DISPLAY"
```

空文字や未設定なら、まずその環境の表示設定を直してください。

### 3) codex CLI

Codex App Server接続を行うので、次が通るかを確認します。

```bash
codex login status
codex app-server --help
```

`codex login status` がコマンドとして動くこと、`codex app-server --help` がヘルプを表示することが最低条件です。

## インストールと起動

### 1. ソースを取得

```bash
git clone https://github.com/salty919/codex_info_v2.git
cd codex_info_v2
```

### 2. 初回起動

```bash
./run.sh
```

`run.sh` は初回時に依存取得とビルドを実施します。初回は時間がかかるため、完了まで待機してください。

### 3. 履歴保存先を明示する（任意）

履歴を別先に置きたい場合は起動前に設定します。

```bash
CODEX_INFO_DATA_DIR="$PWD/data" ./run.sh
```

## 初回認証フロー（確実版）

1. 画面の「認証を開始」を押す  
2. 表示された「認証ページを開く」を押す  
3. ブラウザでOpenAIへログインし、Codexアクセス許可を完了する  
4. X Windowへ戻り「認証状態を確認」を押す  
5. メイン画面の状態が認証済みに切り替わることを確認する

上記で変化がない場合は、  
`codex login status` でCLI側認証状態を確認し、必要なら手順2〜4を再実行してください。

## 初回起動後の確認ポイント（最短チェック）

1. メイン画面が起動し、認証済みと表示される  
2. 残量とリセット時刻が更新される  
3. 7セルゲージの向き・比率が変化する  
4. 法的通知が開ける  
5. Graphを開ける  

ここで最低1つでも詰まると、環境・認証・データ取得のいずれかを疑います。

## 画面・状態確認用環境変数

実際のレビューや再現確認で使う状態は次です。

- `CODEX_INFO_PREVIEW=auth`
- `CODEX_INFO_PREVIEW=normal`
- `CODEX_INFO_PREVIEW=warning`
- `CODEX_INFO_PREVIEW=reset-warning`
- `CODEX_INFO_PREVIEW=error`
- `CODEX_INFO_PREVIEW=zero`
- `CODEX_INFO_PREVIEW=full`
- `CODEX_INFO_PREVIEW=monthly`
- `CODEX_INFO_PREVIEW=unlimited`
- `CODEX_INFO_PREVIEW=idle`
- `CODEX_INFO_PREVIEW=legal`
- `CODEX_INFO_PREVIEW=graph`
- `CODEX_INFO_PREVIEW=graph-old`

最小幅検証をする場合は次を加えて実行します。

```bash
CODEX_INFO_PREVIEW_SIZE=700x480 CODEX_INFO_PREVIEW=normal ./run.sh
```

## トラブルシュート

### 起動しない/真っ黒なとき

`DISPLAY`、`codex app-server --help`、`codex login status` を確認します。  
それぞれが成功していれば、次に`.log`の最終行を確認すると原因が絞れます。

### 認証後も未認証扱いのとき

`codex login status` を再実行し、ブラウザ側の許可結果を見直します。  
許可後にアカウント状態が更新されない場合は、ブラウザを閉じずに再試行します。

### 画面崩れ・はみ出し

```bash
CODEX_INFO_PREVIEW_SIZE=700x480 CODEX_INFO_PREVIEW=normal ./run.sh
```

で再現する状態で崩れるかを確認し、再現条件をメモしてください。
